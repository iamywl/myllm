# LLM 추론(Inference)은 어떻게 동작하는가?

> 1만 글자를 보내면 LLM은 어떤 과정을 거쳐서, 왜 그만큼의 시간이 걸려서, 답을 만들어내는가?

## 전체 흐름 한눈에 보기

```
[사용자 입력 1만자]
       │
       ▼
  ① 토큰화 (Tokenization)        ← CPU, 즉시
       │
       ▼
  ② 프롬프트 처리 (Prefill)       ← GPU 병렬 처리, 수초~수분
       │
       ▼
  ③ 토큰 생성 (Decode)           ← GPU 순차 처리, 가장 오래 걸림
       │
       ▼
  ④ 디토큰화 (Detokenization)     ← CPU, 즉시
       │
       ▼
[사용자에게 응답 출력]
```

---

## ① 토큰화 (Tokenization)

### 무엇을 하나?

사람이 쓴 글자를 LLM이 이해할 수 있는 **토큰(숫자)**으로 변환한다.

```
"안녕하세요" → [12841, 230, 9453, ...]
"Hello"     → [9906]
```

### 왜 필요한가?

LLM은 글자를 직접 읽지 못한다. 숫자(벡터)만 처리할 수 있다.
토크나이저는 텍스트를 LLM의 어휘 사전(vocabulary)에 맞는 조각으로 쪼갠다.

### 한글의 특성

한글은 영어보다 토큰 효율이 낮다.

| 언어 | 1만 글자 | 대략적인 토큰 수 |
|------|----------|-----------------|
| 영어 | 10,000자 | ~2,500 토큰 |
| 한글 | 10,000자 | ~15,000~20,000 토큰 |

한글은 영어 대비 **6~8배** 더 많은 토큰을 사용한다.
이는 대부분의 LLM이 영어 중심으로 학습되었기 때문이다.

### 소요 시간

CPU에서 처리, 거의 즉시 완료 (밀리초 단위).

---

## ② 프롬프트 처리 (Prefill)

### 무엇을 하나?

입력된 모든 토큰을 **한꺼번에 병렬로** 처리하여, 각 토큰의 "의미"를 계산한다.

```
[토큰 1, 토큰 2, ..., 토큰 20000]
         │
    GPU에서 동시에 처리
         │
         ▼
  KV Cache 생성 (각 토큰의 문맥 정보 저장)
```

### 내부에서 일어나는 일

1. **임베딩(Embedding)**: 각 토큰 숫자 → 고차원 벡터로 변환 (예: 5120차원)
2. **Self-Attention**: "이 토큰이 다른 토큰들과 어떤 관계인가?" 계산
   - 모든 토큰 쌍의 관계를 계산 → O(n²) 복잡도
   - 1만 토큰이면 1억 번의 관계 계산
3. **Feed-Forward Network**: 각 토큰의 의미를 정제
4. **이것을 레이어 수만큼 반복**: Devstral-2 123B는 88개 레이어

### 핵심: KV Cache

Attention 계산 결과를 **KV Cache**에 저장한다.
이 캐시 덕분에 다음 단계(토큰 생성)에서 입력을 다시 처리할 필요가 없다.

```
KV Cache 크기 ≈ 2 × 레이어수 × 토큰수 × 히든크기 × 정밀도
```

### GPU에서 어떻게 처리되나?

```
GPU 코어 수천 개가 동시에 작동:

토큰 1  ─→ [코어 1~64]   ─→ 벡터 출력
토큰 2  ─→ [코어 65~128]  ─→ 벡터 출력
토큰 3  ─→ [코어 129~192] ─→ 벡터 출력
  ...        ...
토큰 N  ─→ [코어 ...]     ─→ 벡터 출력
```

**병렬 처리**이므로 토큰이 많아도 비교적 빠르다.
하지만 토큰이 수만 개가 되면 Attention의 O(n²) 때문에 느려진다.

### 소요 시간

- 입력 1,000 토큰: ~1초
- 입력 20,000 토큰 (한글 1만자): ~수십 초
- 입력이 길어질수록 비선형적으로 증가 (Attention의 n² 특성)

## ③ 토큰 생성 (Decode) — 가장 느린 단계

### 무엇을 하나?

다음 토큰을 **하나씩 순차적으로** 생성한다. 이것이 LLM이 느린 핵심 이유다.

```
"프로그래밍이란" → [?]     → "소프트"   (1번째 생성)
"프로그래밍이란 소프트" → [?] → "웨어를"   (2번째 생성)
"프로그래밍이란 소프트웨어를" → [?] → "만드는" (3번째 생성)
  ...
```

### 왜 하나씩만 생성하나?

다음 토큰은 **이전에 생성된 모든 토큰에 의존**하기 때문이다.
"소프트"를 생성해야 "웨어를"을 생성할 수 있다.
이것은 병렬화가 불가능한 본질적인 한계다.

### 한 토큰을 생성하는 과정

```
1. 직전 토큰 + KV Cache를 입력
2. 88개 레이어를 순차적으로 통과
3. 최종 벡터 → 어휘 사전(32,768개 단어) 중 확률 분포 계산
4. temperature에 따라 토큰 선택
5. 선택된 토큰을 KV Cache에 추가
6. 1번으로 돌아가서 반복
```

### 각 토큰마다 필요한 연산량

```
파라미터 125B (1,250억 개)
  × 2 (곱셈 + 덧셈)
  = 2,500억 번의 연산 (250 GFLOPS)
  ÷ GPU 연산 능력
  = 한 토큰당 소요 시간
```

### 소요 시간 (Devstral-2 123B, M4 Max 기준)

실측: **3.3 tokens/sec** → 토큰 하나당 약 0.3초

| 응답 길이 | 토큰 수 | 예상 시간 |
|-----------|---------|----------|
| 한 줄 답변 | ~50 | ~15초 |
| 보통 설명 | ~500 | ~2.5분 |
| 긴 분석 | ~2,000 | ~10분 |
| 아주 긴 응답 | ~8,000 | ~40분 |

## GPU와 CPU는 각각 무엇을 하나?

### 이상적인 경우: 100% GPU

```
[모델 전체] ─→ GPU 메모리(VRAM)

입력 토큰 ──→ GPU에서 전체 처리 ──→ 출력 토큰
```

모든 레이어가 GPU에 있으므로 최대 속도.

### 현실 (Devstral-2 123B on M4 Max)

모델 126GB 중 GPU에 102GB, 나머지 24GB는 CPU/RAM으로 오프로드.

```
레이어  1~71  (81%) ─→ GPU    ← 빠름
레이어 72~88  (19%) ─→ CPU    ← 느림 (병목!)

토큰 처리 흐름:
  GPU 레이어 1 → 2 → ... → 71 → [데이터를 RAM으로 전송] → CPU 레이어 72 → ... → 88
                                         ↑
                                    여기서 대기 발생!
```

### 왜 CPU 오프로드가 느린가?

```
GPU 연산 속도:   ~30 TFLOPS (Metal)
CPU 연산 속도:   ~2 TFLOPS  (약 15배 느림)
GPU↔RAM 전송:   데이터 복사 오버헤드 추가

19%의 레이어가 CPU에 있으면
→ 전체 속도가 CPU 병목에 의해 제한됨
→ 100% GPU 대비 약 30~50% 느려짐
```

### M4 Max 통합 메모리의 장점

일반 PC는 GPU 메모리(VRAM)와 시스템 메모리(RAM)가 **물리적으로 분리**되어 있다.
데이터를 PCIe 버스로 복사해야 하므로 매우 느리다.

```
일반 PC:     GPU ←──PCIe 버스(느림)──→ CPU/RAM
M4 Max:      GPU ←──통합 메모리(빠름)──→ CPU/RAM
```

M4 Max는 통합 메모리(UMA) 구조라 GPU와 CPU가 같은 메모리를 공유한다.
그래서 123B 같은 거대 모델도 돌릴 수 있고, 오프로드 페널티도 상대적으로 적다.

## 전체 타임라인 예시

**"1만 글자(한글) 입력 → 보통 길이 응답"의 경우:**

```
시간 ──────────────────────────────────────────────────→

[토큰화]  [───── 프롬프트 처리 ─────]  [────────────── 토큰 생성 ──────────────]  [디토큰화]
 ~10ms         ~30초~1분                      ~10분 (2,000 토큰)                    ~1ms
  CPU          GPU+CPU 병렬                  GPU+CPU 순차(하나씩!)                   CPU
                                                    ↑
                                              전체 시간의 90%
```

### 왜 생성이 이렇게 오래 걸리나? 정리

| 원인 | 설명 |
|------|------|
| **순차 생성** | 토큰을 하나씩만 만들 수 있음 (병렬화 불가) |
| **모델 크기** | 매 토큰마다 1,250억 개 파라미터 연산 |
| **CPU 오프로드** | 19%의 레이어가 CPU에서 처리 → 병목 |
| **한글 비효율** | 같은 내용이라도 영어 대비 6~8배 토큰 소모 |
| **Attention** | 이전 모든 토큰을 참조 → 대화가 길수록 느려짐 |

## 요약

```
학습(Training)          →  수천 GPU로 수개월 → 모델 파일(.gguf) 생성
                                                      │
추론(Inference)         →  사용자가 질문할 때마다 실행   │
                                                      ▼
  ① 토큰화:   글자 → 숫자 변환              (CPU, 즉시)
  ② Prefill:  입력 전체를 한번에 이해         (GPU 병렬, 비교적 빠름)
  ③ Decode:   답을 한 글자씩 생성            (GPU 순차, 느림 ← 여기가 핵심)
  ④ 디토큰화: 숫자 → 글자 변환              (CPU, 즉시)
```

- **학습**은 한 번만 하면 되고, **추론**은 질문할 때마다 반복된다
- 추론에서 시간이 걸리는 이유는 "한 토큰씩 순차 생성"이라는 구조적 한계
- GPU가 빠를수록, 모델이 GPU에 많이 올라갈수록 빠르다
